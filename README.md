# Resilient

[简体中文](README.zh-CN.md) | **English**

`Resilient` is a Python project scaffold for reproducible experimentation and engineering. The current version provides project conventions, a minimal runnable package, tests, and continuous integration. It does not yet include a specific algorithm, dataset, or pretrained model weight.

## Quick start

Run all commands from the repository root. No command depends on a machine-specific absolute path.

```bash
git clone https://github.com/Morimorerain/Resilient.git
cd Resilient

python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip==24.0
python -m pip install -r requirements-dev.txt

python -m resilient --version
python -m unittest discover -s tests -v
ruff check .
```

On Windows PowerShell, replace the activation command with:

```powershell
.venv\Scripts\Activate.ps1
```

If Python 3.10.8 is unavailable, use `pyenv` to install the version specified in `.python-version`. The project requires Python `>=3.10,<3.11`; the validated baseline is CPython 3.10.8.

## Environment and dependencies

- Runtime dependencies are recorded in `requirements.txt`.
- Development, test, and build dependencies are recorded with exact versions in `requirements-dev.txt`.
- Package metadata and tool configuration are stored in `pyproject.toml`.
- A Python or dependency change must update the relevant dependency files, this section, the corresponding section in `README.zh-CN.md`, and the reproduction log in the same commit.
- Do not commit `.venv/`, Conda environments, or machine-local caches.

## Hardware and system requirements

The current minimal functionality is CPU-only and does not require a GPU:

| Item | Suggested minimum | Baseline validation environment |
| --- | --- | --- |
| Operating system | Linux, macOS, or Windows | Ubuntu/Linux 5.4, x86_64 |
| Python | 3.10.8 | CPython 3.10.8 |
| CPU | 1 core | AMD EPYC 7542 |
| Memory | 256 MB available | 503 GiB system memory |

If future code requires CUDA, a specific amount of GPU memory, or other hardware, update this table and document the CUDA, driver, framework, and hardware versions.

## Datasets and model weights

The initial scaffold does not require a dataset or model weight, so there is currently no download URL. Before adding code that uses an external asset, update the table below and the relevant `data/README.md` or `models/README.md` file.

| Asset | Target path in repository | Download URL | Integrity check | Status |
| --- | --- | --- | --- | --- |
| Dataset | `data/raw/<dataset_name>/` | Not used yet | SHA-256 required | Not introduced |
| Processed data | `data/processed/<dataset_name>/` | Generated by script | Generation command required | Not introduced |
| Model weights | `models/<model_name>/` | Not used yet | SHA-256 required | Not introduced |

Actual contents under `data/` and `models/` are excluded by `.gitignore`; only documentation and empty directory placeholders are committed. Never commit datasets, weights, checkpoints, or large experiment artifacts directly to Git.

## Repository layout

```text
Resilient/
├── .github/workflows/ci.yml   # Automated quality checks
├── AILOG/                    # Local work logs and temporary files; never uploaded
├── data/                     # Data root; actual data is never uploaded
│   ├── raw/
│   └── processed/
├── models/                   # Model weights; actual weights are never uploaded
├── src/resilient/            # Project source code
├── tests/                    # Maintained automated tests
├── AGENTS.md                 # Automated development rules
├── pyproject.toml            # Python package and tool configuration
├── requirements.txt          # Runtime dependencies
└── requirements-dev.txt      # Development dependencies
```

Write generated results to `outputs/`, `runs/`, or `logs/`; these directories are not uploaded. Delete one-off smoke-test scripts, data, and outputs after validation. Convert reusable checks into maintained tests under `tests/`.

## Reproducibility rules

1. Paths must be relative to the repository root or configuration file, or supplied through command-line arguments. Never commit a developer machine's hard-coded absolute path.
2. Randomized experiments must record explicit seeds. When a framework provides nondeterministic operations, record its deterministic settings as well.
3. Every experiment should record the Git commit SHA, command, configuration, environment versions, input asset checksums, and output path.
4. When adding or upgrading a dependency, update the dependency files and both README versions; never change only the local environment.
5. For each new dataset or weight, record the official download URL, license, target path, extracted layout, and SHA-256.
6. Before committing, run tests and static checks, then remove temporary scripts, caches, and smoke-test artifacts.
7. Source code, docstrings, code comments, configuration comments, and CI comments must use English. User-facing documentation is maintained in both English and Simplified Chinese, with English as the primary version.
